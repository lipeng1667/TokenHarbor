# 官网交流页面源文件

两份交付仍使用原路径：

- `../team-background.html`：团队技术背景，7 个内容章节。
- `../tokenharbor-presentation.html`：团队背景与 TokenHarbor 规划，共 17 个内容章节。

页面为连续滚动的原生 HTML，不使用整页截图或幻灯片画布。标题、正文、数据说明、表格和架构节点可选择、搜索与替换；原 PPT 的地图、客户标识、产品截图及必要图形保留为独立素材。桌面多列内容在手机端重新排列，文字保持正常阅读字号。

## 内容维护

| 文件 | 作用 |
| --- | --- |
| `team-sections.html` | 团队背景 7 章的正文、表格与架构节点 |
| `platform-sections.html` | TokenHarbor 10 章的产品与技术规划 |
| `viewer.css` | 全局及历史章节的排版、响应式与打印样式 |
| `platform-visuals.css` | TokenHarbor 专用图示与响应式样式，仅嵌入完整交流页面 |
| `viewer.js` | 目录关闭、当前位置提示与打印按钮增强 |
| `media/` | 从原 PPT 提取的独立图片、局部图形及来源清单 |
| `../../scripts/build-presentations.py` | 组装品牌页首、目录和正文，生成两个单文件 HTML |
| `content-notes.md` | 章节取舍、数据更新口径与待确认事项，不嵌入对外页面 |
| `project-evidence.md` | 核心项目表述的原稿、文档和源码依据，以及证据边界 |
| `platform-evidence.md` | TokenHarbor 十章的 OES 复用依据、验证范围与规划边界 |
| `publication.md` | 官网已发布地址、源版本、交付版本与验收结果 |
| `data-sources.md` | 上一轮公开数据查证档案，本轮不用于核心项目展示 |

在项目根目录执行：

```sh
python3 scripts/build-presentations.py
```

修改上述 HTML 片段即可更新文案。历史架构使用普通 HTML 元素；TokenHarbor 的客户入口、分层架构、调用树、状态泳道和验证流程采用 `.th-*` 专用 HTML/CSS 与少量无文字 SVG 连线。节点、标签和数字均可直接编辑；新样式不覆盖历史章节。Portal、Kernel、Dispatcher 分别使用入口、协调中枢、分发分支三种原创 SVG 图标。图片在源片段中使用 `src="media/文件名"`，构建时自动内嵌为 data URL，保留 `data-source` 来源属性。更新素材后重新构建即可。生成脚本仅依赖 Python 标准库。

## 使用与官网接入

生成的 HTML 内含图片、样式与少量增强脚本，可直接在本地浏览器打开。禁用 JavaScript 时，正文、表格、架构与原生目录锚点仍可阅读使用。页面不加载外部字体、图片或分析脚本，也不依赖本地 PPT、PDF 或项目规划文档。

完整版已发布至[申行科技官网独立 URL](https://shenxingkeji.cn/assets/presentations/tokenharbor-85bd038.html)。发布使用官网现有流程，源文件、构建产物与公网正文的 SHA256 一致；具体版本与验收结果见 `publication.md`。该静态路径使用版本化文件名，后续更新生成新地址，不覆盖已发布的长期缓存文件。页首品牌为文字“申行科技”，没有自造 Logo、联系方式或官网域名。

## 内容口径

团队部分按最新确认精简为七章：QoS 与防骚扰合并；移除商城、智能服务云、集中短信架构三个独立章节；MaaP 在 OES 前，OES 为历史部分末章。短信与号码认证为用户确认由团队搭建的重点产品，两页以原项目历史数字为主要内容。

短信保留伙伴地图，展示 34／260／1397 亿条三条发送记录，以“首个记录年度／次年／第三年”表达原稿顺序；首个记录年度不代表上线年，1397 亿条原文为“至今发送量”，前两条未明确年度或累计口径，不计算年度增幅。主成果卡为日均 600,000,000 条、日最高 1,000,000,000 条、累计接入 8,000+ 家用户（原稿 8,209 家的简写），附一点接入、3 大运营商、7 种协议短条。原稿 200 亿预计收益不列为实绩。

取号展示近 6,000 家 APP、每天超 20 亿次及支持 5G 套餐用户；复原用户体验、企业成本、接入难度、安全性四行圆形定性比较表，标题标为“原稿定性评价”。表中填充表示程度高低，成本与难度越低越好，不把它解释为统一优劣评分或现行成本、安全保证。技术内容保留 App / Web 接入、IPv4 / IPv6 地址处理、4G / 5G 路径分流三项短条；NIS 的完整机制、文件定位和边界保留在 `project-evidence.md` 维护档案。

行业量收变化、全国用户规模、现行运营商 SDK 介绍及行业市场预测不作为项目成果。历史数字通过简短标题和标签标明历史范围及统计口径，来源细节留在维护档案；页面不显示绝对年份，原年份映射只留在维护说明。客户标识与产品截图并非当前客户背书。TokenHarbor 第 08–17 章已按相同配色与图示语言重做：客户价值、概念架构、少输入接入、连续三项技术亮点（成本证据、优化验证、任务恢复）、门槛积累、三组对照、团队经验迁移和实施路径。架构以“接入与负载均衡”等概念职责表达，不绑定产品或展示部署拓扑细节；OES 的模拟下游功能验证与 TokenHarbor 拟建设能力分开标注，不展示未经验证的吞吐或节省比例。详细依据见 `platform-evidence.md`。

原始 PPT/PDF、`original/`、`background.svg` 和 `background-architecture.svg` 仅保留本地，用于内部追溯，**不随此次提交，当前构建也不需要这些资料**。原始资料与既有项目规划未改写。
